# Email Notification Setup

This guide explains how to send SponsorScan email notifications when a report
contains newly discovered jobs.

The email integration is optional. It should run after the personalized report
has created its new-jobs CSV file.

## 1. Requirements

You need:

- a Gmail account that will send the message;
- 2-Step Verification enabled on that Google account;
- a Gmail App Password;
- a recipient email address;
- a generated new-jobs CSV file.

The sender ships as `scripts/send_job_email.py`. Its `--check` flag logs in to
Gmail and stops, so it tests your credentials without sending anything.

Do not use your normal Gmail password in GitHub Actions.

## 2. Create a Gmail App Password

Gmail does not accept your normal password from a script. It needs an App
Password: a separate 16-letter password that only SponsorScan uses, and that
you can delete at any time without changing your real password.

Open each link below in a browser signed in to the Gmail account that will
**send** the alerts. Your profile picture at the top right of each page shows
which account is active; click it to switch.

### Step 1: turn on 2-Step Verification

Open https://myaccount.google.com/signinoptions/twosv

1. Google may ask for your password first.
2. If the page says **2-Step Verification is on**, go to step 2.
3. Otherwise click **Turn on 2-Step Verification** and follow the prompts.
   Google asks for a phone number and texts it a code.

### Step 2: create the App Password

Open https://myaccount.google.com/apppasswords

1. In the **App name** box, type `SponsorScan` and click **Create**.
2. A box titled **Generated app password** shows 16 letters in four groups,
   like `abcd efgh ijkl mnop`. The spaces do not matter.
3. Copy them now. Google never shows them again. If you lose them, delete this
   App Password on the same page and create another.
4. Click **Done**.

If the page says **The setting you are looking for is not available for your
account**, either 2-Step Verification is still off (go back to step 1), or this
is a work or school account whose administrator has disabled App Passwords. A
personal Gmail account avoids the second case.

The Gmail address that creates the App Password must be the same address used in
`GMAIL_ADDRESS`.

### Step 3: test it

Run the `--check` commands in [section 6](#6-test-locally). They log in and
stop without sending anything. **Check passed. Nothing was sent.** means it
worked.

## 3. Add GitHub Actions secrets

In the repository, open:

```text
Settings
  -> Secrets and variables
  -> Actions
  -> New repository secret
```

Create these secrets:

| Secret | Purpose |
|---|---|
| `GMAIL_ADDRESS` | Gmail account used to send messages |
| `GMAIL_APP_PASSWORD` | App Password generated by the same Gmail account |
| `NOTIFICATION_EMAIL` | Address that receives the report |

Example:

```text
GMAIL_ADDRESS=sender@gmail.com
GMAIL_APP_PASSWORD=abcdefghijklmnop
NOTIFICATION_EMAIL=recipient@example.com
```

Do not include these values directly in workflow YAML or committed files.

## 4. What the email script does

`scripts/send_job_email.py`:

1. reads the configured new-jobs CSV;
2. exits successfully without sending when there are no new jobs;
3. builds a short summary of up to 20 jobs, with links;
4. attaches the full CSV;
5. lists any job boards that failed to fetch;
6. logs in to Gmail with the App Password and sends to `NOTIFICATION_EMAIL`.

A no-new-jobs result does not fail the workflow.

## 5. Add the workflow step

`workflows/sponsorscan.example.yml` already includes this step. It skips itself
until all three secrets exist:

```yaml
- name: Email new job matches
  if: env.EMAIL_ENABLED == 'true'
  env:
    GMAIL_ADDRESS: ${{ secrets.GMAIL_ADDRESS }}
    GMAIL_APP_PASSWORD: ${{ secrets.GMAIL_APP_PASSWORD }}
    NOTIFICATION_EMAIL: ${{ secrets.NOTIFICATION_EMAIL }}
    EMAIL_SUBJECT_PREFIX: SponsorScan
  run: python scripts/send_job_email.py
```

A step's `if:` cannot read `secrets` directly, so the job computes
`EMAIL_ENABLED` in its `env:` block. See the example workflow.

Keep the filename consistent with the active profile.

For example, an OPT profile may produce:

```text
opt_new_jobs_48h.csv
```

and a citizen profile may produce:

```text
citizen_new_jobs_48h.csv
```

In that case, set `NEW_JOBS_CSV` to the correct profile-specific file.

## 6. Test locally

Set temporary environment variables in PowerShell. `Read-Host` keeps the App
Password out of your command history:

```powershell
$env:GMAIL_ADDRESS = "sender@gmail.com"
$env:GMAIL_APP_PASSWORD = Read-Host "App Password"
$env:NOTIFICATION_EMAIL = "recipient@example.com"

python .\scripts\send_job_email.py --check
```

When the check passes, send a real message from your report:

```powershell
$env:NEW_JOBS_CSV = "new_jobs_48h.csv"
python .\scripts\send_job_email.py
```

A personalized report names its files after the profile, for example
`casey_new_jobs_48h.csv`; the profile's `output_files` lists them. Nothing is
sent when that file has no jobs in it.

These variables apply only to the current PowerShell session.

On macOS or Linux:

```bash
export GMAIL_ADDRESS="sender@gmail.com"
read -s -p "App Password: " GMAIL_APP_PASSWORD; export GMAIL_APP_PASSWORD
export NOTIFICATION_EMAIL="recipient@example.com"
python scripts/send_job_email.py --check

export NEW_JOBS_CSV="new_jobs_48h.csv"
python scripts/send_job_email.py
```

Do not paste real credentials into screenshots, issue reports, or commit
messages.

## 7. Test through GitHub Actions

Open the repository's Actions tab and manually run the SponsorScan workflow.

Verify:

- the report step succeeds;
- the email step is green;
- an email arrives when the CSV contains new jobs;
- no email is sent when the CSV contains only the header;
- the workflow still succeeds when no email is sent.

Check the spam or junk folder during the first test.

## 8. Recommended email behavior

A useful notification should include:

- the number of new jobs;
- the profile name;
- the report time window;
- company and title;
- location;
- application priority;
- direct application URL;
- the generated CSV as an attachment when useful.

Avoid sending the entire job description in the email. Keep the message easy to
scan and link back to the original posting.

## 9. Multiple profiles

When running SponsorScan for multiple users, each profile should have its own:

- new-jobs CSV;
- recipient address;
- state file;
- workflow job or matrix entry.

Do not send one user's personalized report to another user's email address.

For a public repository, store only example workflow configuration. Each user
should create their own repository secrets.

## Troubleshooting

### Gmail authentication fails

`python scripts/send_job_email.py --check` reproduces the login on its own.
Confirm all of the following:

- `GMAIL_ADDRESS` is a personal or workspace Gmail account;
- `GMAIL_APP_PASSWORD` is an App Password, not the normal account password;
- the App Password was created by the same account in `GMAIL_ADDRESS`;
- 2-Step Verification is enabled;
- no extra quotation marks or spaces were saved in the GitHub secret.

Do not use the Google Sheets service-account email as `GMAIL_ADDRESS`. A service
account can update the spreadsheet but is not the Gmail inbox sending the
message.

### The workflow succeeds but no email arrives

Check whether the new-jobs CSV has any data rows.

The sender skips email when the file contains only its header.

Also check:

- spam or junk folders;
- the value of `NOTIFICATION_EMAIL`;
- whether the workflow used the correct profile-specific CSV filename.

### The script cannot find the CSV

Confirm the report step creates the file before the email step runs.

List files in the workflow for debugging:

```yaml
- name: List generated files
  run: ls -la
```

On a Windows runner:

```yaml
- name: List generated files
  run: Get-ChildItem
```

### The App Password stopped working

Google may invalidate App Passwords after account-security changes. Generate a
new App Password and update `GMAIL_APP_PASSWORD` in repository secrets.

## Security

Never commit:

- Gmail passwords;
- Gmail App Passwords;
- personal recipient addresses in public configuration;
- `.env` files containing credentials;
- workflow logs containing secret values.

GitHub masks configured secrets in logs, but scripts should still avoid printing
credential values.
